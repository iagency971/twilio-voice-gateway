## 2. Geometry-neutral provenance instrumentation

The historical v0.4 display output is the geometry authority. Provenance is added only as a sidecar. A parity gate must prove exact equality of every displayed row on the pilot source for:

### ESM provenance

Each causal ESM state receives an immutable `source_state_id` at state birth. The ID is retained when that same state is updated by the frozen causal matching rule. New unmatched observations receive new IDs.

### EWM provenance

Each causal EWM state receives an immutable `source_state_id` at state birth and retains it through the frozen state update rule.

### EPM provenance

Each pivot-memory event receives an immutable event ID from its causal source record: family/configuration, timeframe, radius, pivot index/time, confirmation time, pivot low and frozen event bounds. The event ID does not depend on future contact/reaction.

### ES provenance

The ES family is recomputed from confirmed pivot records rather than stored as a persistent state. Therefore no artificial persistent state ID is invented. Each ES candidate stores the deterministic sorted set of constituent confirmed-pivot IDs. That constituent set is its causal provenance at that snapshot.

### Z4 provenance

Z4 identity may be retained for QA/context, but Z4 rows are not eligible model rows.

## 3. Display-episode identity V1

Episode identity is reset across any non-contiguous C5 gap or NY-session boundary.

Cross-family continuation is forbidden.

Within contiguous C5 snapshots:

- ESM: continuation requires identical `source_state_id`;
- EWM: continuation requires identical `source_state_id`;
- EPM: continuation requires identical immutable pivot-event ID;
- ES: continuation requires the same family and at least one shared constituent pivot ID.

For ES many-to-many cases, a deterministic one-to-one assignment is applied using, in order:

1. largest shared constituent count;
2. largest Jaccard similarity of constituent sets;
3. smallest absolute center distance;
4. lexicographically smallest prior episode ID;
5. lexicographically smallest current provenance signature.

A prior episode can continue into at most one current child; a current row can inherit from at most one prior episode. Unmatched rows start new display episodes.

`display_slot_rank` never defines identity.

## 4. Model-feature whitelist

The V1 model contains exactly three pre-contact features:

1. `zone_width_v = (zhi-zlo)/v_snapshot`;
2. `display_persistence_c5`, starting at 1 and incrementing only across valid display-episode continuation;
3. `current_family`.

`origin_family` is removed because cross-family continuation is forbidden and it is redundant with `current_family`.

`display_persistence_c5` is explicitly a **display persistence** measure, not an intrinsic physical age of a market level.

Excluded from the model include slot/rank, distance to current price, upper-Z4 geometry, current close, contact/penetration/rejection/execution variables and every future-price outcome.

## 5. Information timing

Raw M1 timestamps are bar-open timestamps.

For a row with `snapshot_time_utc = t`:

- `bar_open_time_utc = t`;
- `bar_close_time_utc = t + 1 minute`;

A snapshot may be used for a contact bar only when:

`feature_available_time_utc <= contact_bar_open_time_utc`.

No feature derived from the close of a bar is treated as available at that bar's open.

## 7. Reaction automaton — code may be tested only on synthetic data before GO

The real reaction labeler is implemented and frozen before outcome opening, but during this repair stage it may run only on synthetic fixtures.

### Arming

A display episode may arm after a completed M1 close strictly above the **latest causally available** episode `zhi`. Arming becomes effective at that bar close. The arming bar cannot also be a contact bar.

If the display episode disappears before contact, the episode terminates and its arm state terminates.

### Contact

After arming, contact is the first subsequent M1 bar whose range intersects the latest causally available displayed episode geometry `[zlo,zhi]`.

At contact, freeze:

- `zlo0`, `zhi0`, `center0`;
- `v0`;
- the three model features;
- the pre-contact feature snapshot and its availability time.

### Contact-bar ordering

A favorable high on the contact bar is **never** counted as a favorable reaction because OHLC M1 cannot establish that it occurred after the contact.

If the contact bar closes strictly below `zlo0`, classify `INVALIDATION_FIRST` immediately.

Otherwise favorable-event eligibility begins with the next completed M1 bar.

### Primary favorable/invalidation events

`F = zhi0 + 0.50 * v0`.

On bars after contact:

- favorable if `high >= F`;
- invalidation if confirmed `close < zlo0`.

If both occur on the same M1 bar, classify `AMBIGUOUS_SAME_BAR` and assign primary binary label 0.

Primary binary label:

- 1: `FAVORABLE_FIRST`;
- 0: `INVALIDATION_FIRST`, `AMBIGUOUS_SAME_BAR`, `NEITHER`.

### Window and session end

Evaluate at most the next 30 **available completed M1 bars after the contact bar**, truncated at 17:00 New York. A bar opening at 16:59 and closing at 17:00 is eligible; a 17:00-open bar is not.

Missing M1 minutes are skipped as unavailable bars and counted/reported. Duplicate timestamps with conflicting OHLC fail closed.

Retests are excluded from the primary population.

Different provenance episodes may contact on the same bar; dependence is handled statistically by clustering on NY session date.

## 8. Model and preprocessing

Exactly one candidate model is allowed after a future GO:

- logistic regression;
- L2 penalty;
- `C=1.0`;
- solver `lbfgs`;
- `max_iter=5000`;
- no class weighting;
- no hyperparameter search;
- no alternative algorithm competition.

Preprocessing learned on DEV only:

- `zone_width_v`: mean/SD standardization with population SD (`ddof=0`);
- `display_persistence_c5`: `log1p` then DEV mean/SD standardization with `ddof=0`;
- zero or non-finite DEV SD fails closed;
- `current_family`: lexicographically sorted DEV vocabulary, first category as reference;
- unseen later family maps to all-zero family indicators and is counted;
- no imputation; rows missing any model feature are excluded and counted.

Convergence warning or non-convergence fails closed.

The continuous score is the logistic `decision_function` logit. Predicted probability is descriptive only and must not be called calibrated.

## 9. Rank and quartiles

For score `s`, the frozen DEV empirical rank is the midrank CDF:

`(count(DEV_score < s) + 0.5 * count(DEV_score == s)) / N_DEV`.

DEV quartile cutpoints use `numpy.quantile(..., method='linear')` at 0.25, 0.50 and 0.75.

Fixed intervals:

- Q1: `score <= q25`;
- Q2: `q25 < score <= q50`;
- Q3: `q50 < score <= q75`;
- Q4: `score > q75`.

Empty quartiles or tied cutpoints that prevent all four non-empty groups make the quartile gate unavailable/fail; cutpoints are never moved to improve the result.

## 10. Primary association and bootstrap

Continuous association is exactly:

`ROC_AUC(continuous_logit, primary_binary_label) - 0.5`.

Cluster bootstrap:

- cluster = complete `session_date_ny`;
- 5,000 resamples;
- seed `20260829`;
- sample session dates with replacement;
- include every eligible episode from each sampled session with the session's multiplicity;
- percentile 95% CI = 2.5th and 97.5th percentiles of valid resamples;
- single-class resamples are invalid and omitted;
- fewer than 4,750 valid resamples makes the CI gate unavailable/fail.

The Q4-Q1 success-rate difference uses the same cluster-bootstrap rules.
